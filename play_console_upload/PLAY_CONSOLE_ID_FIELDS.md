# Play Console 三个 ID 对照卡（别搞混）

> 2026-11-12 核对。适用于「一次性商品 / One-time products」新模型。

---

## 先给结论：现在**不用填优惠 ID**

「优惠 ID」属于**折扣优惠 / 预购优惠**，是**可选**的营销对象。
官方《一次性商品概览》里，「添加折扣优惠」的路径是：

> 一次性商品页 → 点商品右侧箭头 → 「修改一次性商品」→ **「购买选项和优惠」→ 添加优惠 → 折扣**

也就是**商品创建完成之后**才有的入口。当前你还在「创建一次性商品 → ② 供应情况和定价」这一步，
按既定方案只是**按 $2.99 正常售卖**，不需要任何优惠：

- 页面上如果看到「添加优惠 / 创建优惠 / 优惠 ID」→ **直接跳过、别点进去**；
- 已经误点进去了 → 返回上一步 / 取消，不用保存草稿；
- 继续走：Set prices → 批量修改价格 → `2.99` / USD → 保存 → **启用**。

> 官方原文（订阅文档，一次性商品同理）：「**您可以选择是否提供优惠。即使不创建优惠，也可以提供基本方案**」。

---

## 三个 ID 是什么

| ID | 属于哪个对象 | 本项目的值 | 什么时候填 | 能否改 |
|---|---|---|---|---|
| **商品 ID** | 一次性商品 | `pro_unlock` | 第 1 步「商品详细信息」，**必填** | ❌ 创建后永久不可改 / 不可删 / ID 不可复用 |
| **购买选项 ID** | 购买选项 | `buy` | 第 2 步「购买选项」，**必填** | ❌ 不可变；同一商品内唯一 |
| **优惠 ID** | 折扣优惠 / 预购优惠 | **不建优惠就不填** | 商品建好后，主动点「添加优惠」才出现 | ❌ 启用后不可改、也不可复用于其它优惠 |

三者是父子关系：`商品 → 购买选项 → 优惠`。

---

## 万一确实要建折扣优惠（比如首发限时 5 折）

**优惠 ID 规则**（官方 `monetization.onetimeproducts.purchaseOptions.offers` API 字段定义）：

- **必需、不可变**；在**同一购买选项内唯一**
- 必须以**数字或小写字母开头**
- 只能包含：**小写字母 a-z、数字 0-9、连字符 `-`**
  ⚠️ **不能用下划线 `_`、不能用大写**（这点和「商品 ID」允许下划线不同，最容易写错）
- 最长 **63 字符**
- 用户看不到

可用示例：

```
launch-2026
pro-launch-50
```

不要写：`Launch_2026`（大写+下划线不行）、`pro_launch`（下划线不行）。

同一页还要填：优惠类型（**绝对折扣 / 百分比**）、起止时间（可设无限期）、可选标签、可选限购数量、
地区供应与折扣，最后 **保存 → 启用**。

## ⚠️ 技术侧：现在别建优惠

`ProManager.kt` 用的是**单数** getter：

```kotlin
d.oneTimePurchaseOfferDetails?.formattedPrice     // 显示价格
d.oneTimePurchaseOfferDetails?.offerToken         // 购买参数
```

它只返回「向后兼容的 buy 购买选项」，**不是** `getOneTimePurchaseOfferDetailsList()`。
所以建了折扣优惠后，可能出现：

- App 关于页仍显示原价 `$2.99`（来自 `formattedPrice`），而 Play 结算按折扣价；
- 或优惠的 offerToken 没被选中，走的还是标准购买选项。

→ **初版不要建优惠**。要做首发折扣，先用「**促销代码 / 优惠码**」（另一个页面：
借助 Play 变现 > 商品 > 促销代码），或者先改代码支持多优惠并真机验证价格显示，再上折扣。
按规矩这属于功能改动，得先出方案、再落码。

---

## 「促销代码」不是「优惠 ID」

促销代码页填的是「**促销活动名称**」和码的数量/类型（一次性码 / 自定义码），
不是 `offerId`。自定义码要求字母数字、不区分大小写、同一 App 内唯一，建议带年份便于追踪。
两者别混。
