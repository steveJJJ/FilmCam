# Relic Cam — Google Play「收费相关」表单逐字段填写指南

> 核对时间：2026-11-12；应用 `com.filmcam.app` / Relic Cam；依据 Google Play 官方帮助页与当前项目代码。
> 本文件只讲**跟钱有关的 4 个页面**，按顺序填；其它上架项见 `PLAY_CONSOLE_CHECKLIST.md`。

---

## 0. 一句话结论 + 一条不可逆红线

**既定变现方式：免费下载 + 一次性内购 `pro_unlock` 解锁工程模式。**
所以「应用定价」页选 **免费（Free）**，「收费」只发生在后面那个 `pro_unlock` 商品上。

> ⚠️ **不可逆**：应用一旦设为「免费」，**永远不能改回付费**。想改成付费下载，必须用**新包名新建应用**。
> （反向可以：付费 → 免费随时能改。）
> 如果你这次其实是想做「付费下载、一次性买断」，**先别点「免费」**，告诉我重新出一版填写方案。

## 1. 先分清 4 个不同页面（别在一个页面里找全部）

| 顺序 | 页面 | 新版菜单路径 | 作用 | 你现在的状态 |
|---|---|---|---|---|
| ① | **付款资料 / 商家账号** | Play Console → 设置 → 开发者账号 → 付款资料；或 `payments.google.com` | 收钱、交税、验证银行 | 已提交、银行账户改用储蓄卡 → **先确认「已验证」** |
| ② | **应用定价** | **商品 > 应用定价**（旧版：商店发布 > 定价和分发范围） | 决定 App 本身免费还是付费 | **待填：选免费** |
| ③ | **一次性商品** | **通过 Google Play 创收 (Monetize with Play) > 商品 (Products) > 一次性商品 (One-time products) > 创建一次性商品** | 建 `pro_unlock` 并定价格 | **待建** |
| ④ | **许可测试** | 设置 > 许可测试 (License testing) | 自己免费测购买流程 | 待加测试账号 |

> 页面名变动：旧的「**应用内商品 (In-app products)**」在 2025 年后改叫「**一次性商品 (One-time products）**」。
> 代码 `ProManager.kt` 用的 `ProductType.INAPP` **就是**一次性商品，两者直接对应，用新版页面即可。
> 另外 **2025-10-27 起定价模板已停用**，价格必须逐个商品设置，别再找「定价模板」入口。

## 2. 页面 ① 付款资料 / 商家账号（收款与税）

**先做这一步**：`payments.google.com` → 设置 → 付款方式，确认银行账户状态是「**已验证**」。
「正在验证」就等 1~3 个工作日，可能要回填 Google 打来的小额打款金额、或上传 90 天内对账单。

| 字段 | 怎么填 | 踩坑 |
|---|---|---|
| 账户类型 | **与注册开发者账号时的主体一致**（个人就选个人，组织就选组织） | 选错后极难修改，可能需要联系客服 |
| 法定姓名 / 公司名称 | 与证件、银行开户名**逐字一致**（拼音大小写也要一致） | 姓名不符 → 汇款被退回 |
| 地址 / 电话 / 支持邮箱 | 真实有效，与证件一致 | Google 可能寄信核验；含内购的应用会在商店页展示开发者地址 |
| 银行账户 | 账户持有人姓名、银行名、账号、**SWIFT/BIC**、银行英文地址 | 中国大陆一般走美元电汇；不支持支付宝/微信/人民币直连 |
| **税表** | 非美国税务居民：个人 **W-8BEN** / 组织 **W-8BEN-E**，声明中国税收居民；填完看页面显示的适用预扣税率 | **不填会被按最高 30% 预扣**；税务信息缺失会冻结结算 |
| 默认币种 | 中国开发者账号 = **美元 (USD)**（官方《支持开发者和商家注册的地区》表：中国 ✔ 开发者注册 / ✔ 商家注册 / 美元） | 后面填基准价时填 **USD**，不要把 `¥18` 当基准价直接输进去 |

**费率与到账**：标准服务费 30%（订阅满一年等计划为 15%，部分市场 2026 年有新档位，以结算报告为准）→ 到手约 70%；按月结算，通常次月 15 日左右汇出上一个月收入，低于门槛自动累积。
⚠️ 中国大陆**消费者端**不是 Google Play 正式付费市场，所以这个内购主要面向**海外用户**；不要按「国内用户能买」来设计价格。

## 3. 页面 ② 应用定价（免费）

路径：**Play Console → 商品 > 应用定价**（旧界面：商店发布 > 定价和分发范围）。

| 字段 | 填写值 |
|---|---|
| 应用类型 / 「此应用是」 | **免费 (Free)** ← 点「将应用设置为免费应用」 |
| 价格 / 基准币种 / 各国本地价 | **选免费后这些都不用填**（只有付费应用才输价格） |
| 含税设置 | 免费不涉及；内购的税务在页面 ③ 里配 |
| 国家/地区 | 默认全选即可（可按需裁剪；未分发的国家即使设价也拿不到 App） |
| 设备分类 / 其他 Android 计划 | 手机 + 平板（App 支持横竖屏）；其余按需 |
| Managed Google Play（企业分发） | 不勾 |
| 出口合规等勾选项 | 按实际勾选，App 无联网、无加密出口问题 |

保存后可能要**几小时**才在 Play 上生效。免费应用**照样可以有内购**，这是既定方案。

## 4. 页面 ③ 一次性商品 `pro_unlock`（真正「收费」的地方）

### 4.1 四个前置条件（缺一条这个菜单不会出现 / 不能创建）

1. 页面 ① 付款资料**已创建并验证**
2. 页面 ② 应用定价**已设过一次**（免费/付费）
3. **已上传至少一个 AAB 到任一轨道**（内部测试即可，不用发布）→ 传 `RelicCam-v1.0.0-vc72.aab`
4. App 有 `com.android.vending.BILLING` 权限 —— ✅ 代码里已有（`AndroidManifest.xml:37`，billing 9.1.0）

### 4.2 逐字段照抄

> 📋 **可直接复制的文案见 `PLAY_PRODUCT_COPY.md`**。截图实测字段上限：名称 ≤ 55 字符、说明 ≤ 200 字符；
> 默认语言是 **en-US**（中文用「管理翻译」加），标签与图标均可留空。

| Console 字段 | 填写值 | 说明 / 代码对照 |
|---|---|---|
| **商品 ID** | `pro_unlock` | ⚠️ **创建后永久不可改、不可删除、ID 也不能复用**；必须和 `ProManager.kt:32` 的 `PRODUCT_ID` 一字不差 |
| 名称 | en-US `Engineering Mode (Pro)`；zh-CN `工程模式（Pro）` | 会显示在**购物车**里，别塞说明性长串；可后期改。中文通过「管理翻译」添加 |
| 描述 | 见 `PLAY_PRODUCT_COPY.md`（en-US 183 字 / zh-CN 约 110 字） | 必须与代码实际权益一致：慢门档位、输出风格、按卷冲洗参数、色彩微调、镜头柔度。明确「不是订阅」；⚠️ 不要写「唯一解锁方式」——关于页连点版本号 10 次的免费彩蛋入口也在 |
| 图标 | 可留空 | 非必填 |
| **税务、法规遵循和计划** | 按页面引导完成税务设置；数字内容类目；面向欧盟注意撤回权相关选项 | 原来旧版叫 `Withdrawal Right Type: DIGITAL_CONTENT` |
| **购买选项 ID** | `buy`（或 `buy-pro`，自定义但唯一） | 一个商品至少要有一个购买选项 |
| 交易类型 | **购买 (Buy)**，不要选「租借 (Rent)」 | 工程模式是永久解锁 |
| 高级选项 → 内容类型 | **数字内容 (Digital content)**，不选「服务」 | 功能解锁属于数字内容 |
| 高级选项 → 数量/上限 | 不启用 | 一次性权益，不能买多份 |
| 向后兼容 | **不用管**（官方：首个「购买」购买选项**自动**标记为向后兼容；本项目 `billing:9.1.0` 走新模型，只有 PBL 7 或更旧才需手动标） | 代码用单数 `oneTimePurchaseOfferDetails` 取价格和 `offerToken` → 所以**只建 1 个购买选项**最稳 |
| **购买选项数量** | **只建 1 个** | 代码取 `oneTimePurchaseOfferDetails`（单数）；建多个会取到哪一个不确定 |
| 地区供应情况 | 默认「所有地区可用」；如需裁剪用「编辑供应状态和访问权」 | ⚠️ 大量「SKU 查不到」是地区没开放；且**应用未上架的地区，用户也买不了** |
| 价格 | 基准填 **USD 2.99**（约 ¥21）作起点，各区域由 Google 自动换算本地币种并加税；可逐个手动改 | 中国账号默认币种是 USD，别把 `¥18` 当基准价输进去。想调价随时可改 |
| **保存 → 启用 (Activate)** | **必须点！** 中文界面按钮叫「**启用**」，不是「激活」 | ⚠️ 只保存不启用 = 停在草稿，用户点购买什么都不弹；`ProManager.kt:138` 会静默打日志「未查到商品」 |
| 批量设价路径 | 右上 **Set prices → 批量修改价格** → 全选地区 → 填 `2.99` / USD → 应用 → 继续 | 表格里价格为 `-` 就是还没设价；「税额」列由系统自动算，不用改 |

### 4.3 代码侧对照（确认不会填错）

| 代码 | 依赖的 Console 字段 |
|---|---|
| `ProManager.PRODUCT_ID = "pro_unlock"` | 商品 ID |
| `setProductType(BillingClient.ProductType.INAPP)` | 一次性商品（不是订阅） |
| `enablePendingPurchases(...enableOneTimeProducts())` | 一次性商品模型，billing 9.1.0 已支持 |
| `d.oneTimePurchaseOfferDetails?.formattedPrice` | 唯一且向后兼容的 Buy 购买选项价格 |
| `launchBillingFlow(...setOfferToken(...))` | 该购买选项的 offerToken |
| `acknowledgePurchase(...)` | 非消耗型，购买后需确认（代码已处理） |

## 5. 页面 ④ 许可测试（提交审核前）

设置 → **许可测试** → 把自己的 Google 账号加进测试列表，许可响应设为 `RESPOND_NORMALLY`（或按 Play 当前文案选「测试购买」）。⚠️ 不在列表里的账号，即使在测试轨道购买也会**真实扣款**。
装机两条路：**A（推荐）** 从内部测试轨道经 Play 商店安装；**B（官方允许）** 许可测试员可**侧载**，条件是包名一致 + 设备 Google 账号就是许可测试员 + Play 商店最新版（官方结算测试文档明确可绕过签名检查）。进关于页点「工程模式 PRO」走一遍购买流程 —— 测试购买不真实扣款。详见 `PLAY_PRODUCT_ACTIVATE.md`。

## 7. 最容易踩的 7 个坑

1. **把 App 设成免费后想改付费** → 不可逆，只能换包名重建（本项目包名 `com.filmcam.app` 不能改）。
2. **商品没点「激活」** → 点购买毫无反应，日志静默。
3. **商品 ID 写错或大小写不一致** → 查不到商品；且 ID 永久不可改、删了也不能复用。
4. **没上传过 AAB** → 「一次性商品」页面不出现 / 不能创建。
5. **付款资料没验证 / 税表没填** → 结算被冻结或按 30% 预扣。
6. **基准价填成人民币** → 中国开发者账号默认币种是 USD。
7. **只保存没点「启用」、或建了多个购买选项** → 前者商品停在草稿买不了；后者代码取单数 `oneTimePurchaseOfferDetails` 时价格和 offerToken 不确定。
