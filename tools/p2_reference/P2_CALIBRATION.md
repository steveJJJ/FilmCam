目的：把「FilmCam 成片更贴近真 T3」的校准工作建立在**网络可得的定量参照**上，
不再等用户实拍对照。本目录就是参照物库，本文档是使用说明书。

**跨层一致的可信结论**（≥2 层印证）：
1. UltraMax 显著比 Gold 冷（Brooklyn 实验室评测同结论）
2. Pro 400H 饱和度垫底（粉调/柔和），且物理上红层斜率反超
3. 反转片饱和度整体高一档（Provia 最高）
4. 富士民用卷（C200/Superia）绿轴显著偏绿，柯达 Gold 偏橄榄黄
5. Portra 800 是波特拉系最暖（橙罩也最厚）
6. Gold 的签名是「黄琥珀压中间调 + 蓝被压弱 + 高光缓降/暗部速降的不对称反差」

## 三、扫描仪签名（出口三档的依据，与现行代码核对 ✓）

网络多源一致结论（EFAS lab-look 研究、Optik Oldschool、Studio V、filmdevelopingnearby）：

| 维度 | Frontier（SP-3000） | Noritsu（HS-1800） |
|---|---|---|
| 色轴 | **黄-蓝轴**：青蓝暗部、金色肤色、整体偏冷 | **品红-绿轴**：中性黑位、桃粉肤色、暖中间调 |
| 反差 | 陡、"pre-graded"、HyperTone 压高光 | 平、"like RAW"、暗部留细节 |
| 黑位 | 深蓝黑，可能压死 | 中性或略抬，欠曝帧偏绿 |
| 饱和 | 高 | 柔和（Harman 官方建议 Chroma 90 = 减 10%） |
| 颗粒 | 平滑带彩色变化 | 锐利、偏单色 |

**与 FilmStockMapper.fullExtraEntries 现行值核对**：
- Frontier: y=+1.0（正=冷 ✓）、m=+0.8（正=青绿 ✓「更绿植被」）、gamma 1.06（更陡 ✓）、曝光 −0.18EV（偏亮 ✓）——**全部方向正确**
- Noritsu: y=−1.0（暖 ✓）、m=−0.8（洋红 ✓）、gamma 0.94（更平 ✓）、+0.15EV ——**全部方向正确**
- 唯一可微调项：Noritsu 饱和度可考虑略降（对应 Chroma 90），但 dir_couplers 属胶片特性，
  我们两档都钉在 1.0 的决策维持不变（见 cb6d997 的教训）
- Harman 给 Frontier 的建议 gamma 修正（暗部+4/中间−2）与 scene_latitude 参数族可对照微调

## 五、校准操作流程（下一步怎么用这些靶子）

1. **选 GOLD 200 为基准卷**（用户主力、素材最全、签名最鲜明）
2. 手机拍固定场景（客厅窗光）→ 外放 `spektra_matrix.json`，网格扫
   `y_filter_shift ∈ {−0.5, 0, +0.5}` × `m_filter_shift ∈ {−0.5, 0, +0.5}` ×
   `density_curve_gamma ∈ {0.94, 1.0, 1.06}`
3. `matrix_out/` 小图 pull 回来用 RefAnalyze 同一套指标统计
4. 与靶点表对照：Gold 200 印相档目标 = 暖度显著为正（R−B ≥ +15 量级）、
   绿轴 −3 左右（橄榄）、饱和 0.3-0.35、暗部黑死快/高光缓降（p1 低、p99 高）
5. 其它卷逐支过：Portra 系目标暖度 +13~+33 梯度、UltraMax 压到 +2、
   富士卷绿轴 +5——**逐卷微调应通过引擎 film_stock profile 本身达成**，
   只有引擎 profile 偏离靶点且无参数可修时，才考虑加逐卷 output 参数（要过 ENGINE_KNOWN_KEYS 白名单）
6. datasheet 数据（redlamp_data/）用来验证引擎 profile 的相对差：
   如引擎渲出来的 Superia 绿轴没有显著高于 Gold，那就是 profile 问题不是出口参数问题

## 六、遗留问题

- CIELAB 数据源（frameandfocal）无法独立核验，仅作方向参考
- Flickr 样片的扫描仪未知（可能混有 Frontier/Noritsu/家用扫描），
  统计只取相对序、不取绝对值
- 每支卷 6 张的样本量小，个别卷（Velvia 反差）已有可见场景偏差
- 后续有用户真机 T3 对照时，本表所有数字要重新标定一次（web 素材是靶子，不是真值）
